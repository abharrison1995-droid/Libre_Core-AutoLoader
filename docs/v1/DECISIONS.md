# V1 decisions

| ID | Decision | Reason | Status |
|---|---|---|---|
| D-001 | Preserve the existing package layout and incrementally stabilize entry points, orchestrator and screens. | Matches the specification's architecture-preservation constraint and keeps changes reviewable. | Active |
| D-002 | Unimplemented build, write or verification workflows must report unavailable and cannot unlock subsequent hazardous actions. | A progress animation or static report is not evidence of an operation. | Active |
| D-003 | The standalone `verify_flash` helper remains the public function API; it currently delegates correctly to `FlashVerifier.verify_flash`. | The reported import mismatch is absent in baseline `d5e6810`; add coverage rather than introduce a needless API rewrite. | Active |
| D-004 | Hardware tests will be recorded as pending until the named physical device passes the workflow and boot/function checks. | Software tests cannot validate hardware compatibility or recovery. | Active |
| D-005 | Physical flashing, IVprep downgrade execution, recovery writes, and destructive media operations are excluded from autonomous software work. | These require explicit human authorization and suitable real hardware. | Active |
| D-006 | IVprep is an explicit external human handoff; do not bundle or execute upstream downgrade binaries from AutoLoader. | Upstream IVprep targets Win64 and warns that power loss during downgrade can brick the device; 1vyrain's exact compatibility rule must be pinned and validated. | Active |
| D-007 | Phase 02 compatibility is limited to explicit T430/1vyrain, regular X200/Libreboot and X220/Coreboot profiles; broad database flags never authorize a workflow. | Identity, BIOS, chip topology, region map, programmer and artifact evidence must agree; unknown evidence blocks authorization. | Active |
| D-008 | At Phase 02 acceptance, write requests consumed a one-use approval bound to current evidence digests and then returned `WRITES_DISABLED_PHASE_02`. | This was the fail-closed boundary for that phase. Phase 10B later superseded the block only for guarded X200/X220 external SPI write/read-back; T430 remains a separate human IVprep/1vyrain handoff, and internal SPI plus raw restore/recovery writes remain blocked. | Historical — superseded in part by Phase 10B; hardware acceptance pending |
| D-009 | `NoNewPrivileges=0` is permitted only inside a sealed, no-network offline build VM guest; the host remains unprivileged with no capabilities, and no host share or passthrough grants guest access. | The guest may need helper behavior that `NoNewPrivileges=1` suppresses. The packaged templates specify NNP=1 for preflight and NNP=0 for the fixed builder unit, but there is no production deployment pin and no operational guest evidence proving the effective runtime state. The prototype remains unavailable; this policy decision does not enable a build or any firmware write. | Active — implementation and native operational proof pending |
