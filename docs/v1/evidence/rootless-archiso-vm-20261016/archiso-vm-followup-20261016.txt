Disposable Arch VM follow-up — 2026-10-16
========================================

Scope
-----

This is failure-path evidence only from the disposable QEMU Arch VM. It is not
a successful Archiso build, Live USB boot, ROM build, hardware test, or media
write. The VM ran kernel `6.15.8-arch1-2` with `archiso 91-1`,
`arch-install-scripts 31-2`, `shadow 4.20.0.arch1-1`, and `libcap 2.78-1`.
The rootless build account was UID/GID 1000 with only its private primary
group and subordinate UID/GID ranges `100000:65536`.

Rootless devtmpfs capability
----------------------------

The disposable VM's parent mount table SHA-256 was
`7f0fe2fc7a05032c8b5ff61061905eeed3fcc57b716f88f5267a0ea401ce359c` both
before and after the probe. The probe created a route-free network namespace,
dropped to `fwbuild`, then entered a mapped mount namespace. The command shape
was:

    unshare --net --fork -- setpriv --bounding-set=-all,+setuid,+setgid --reuid=1000 --regid=1000 --clear-groups -- unshare --map-auto --map-root-user --mount --fork -- sh -c 'id; cat /proc/self/uid_map; ip -j route show; mkdir -p /tmp/lc-devtmpfs-probe-20261016/dev; mount -t devtmpfs -o nosuid,mode=0755 devtmpfs /tmp/lc-devtmpfs-probe-20261016/dev; result=$?; echo DEVTMPS_MOUNT_RC=$result; exit $result'

Observed UID map:

    0       1000          1
    1     100000      65536

`ip -j route show` returned `[]`. The devtmpfs mount command returned status
32 and printed `permission denied`; the rootless command also returned 32.
The mount table hash remained the same before and after, so the denied attempt
left no mount in place. This confirms the `devtmpfs` preflight blocker in this
VM; it does not test a successful rootless Archiso execution path.

first in `PATH`, the direct command was:

    /usr/bin/mkarchiso -v -C /dev/null -w /mnt/archv1/work/rc-snapshot/librecore-autoloader-mkarchiso2-vmproof/work -o /mnt/archv1/work/rc-snapshot/librecore-autoloader-mkarchiso2-vmproof/output /mnt/archv1/work/rc-snapshot/Libre_Core-AutoLoader/usb_builder/archiso_profile

It returned **1** during package installation. The log contained both
`no usable package repositories configured` and
`Failed to install packages to new root`; the report listed no `.iso` output
and status `EXPECTED_FAILURE_NO_ISO`. This proves the tested failure path exits
nonzero and does not publish an ISO. It does not prove a successful package
inventory, signature verification, build, or staged-pacstrap lookup across a
successful mkarchiso run.

`a301a034b2ef697b85e22d46d41c3cbe9ca1448c90b8cd5e3c85ef45c3ff780b` and
