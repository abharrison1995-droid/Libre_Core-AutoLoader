## Scope

`autoloader/rom_builder/artifact_engine.py` contains an immutable recipe allowlist, build request/result values, source audit, command/log records, CBFS inventory, tool evidence, artifact records, and JSON manifests with a detached SHA-256 sidecar. X220 records also bind the full-chip result to original-backup manifests, the original chip digest, parser/tool hashes and the non-BIOS regions that must be preserved. `CorebootBuilder` and `LibrebootBuilder` preserve their old public classes as adapters but reject the unpinned generic paths. `PrebuiltManager` no longer fabricates a release catalog, downloads arbitrary images, or invokes blob injection; its constructor does not create an output directory, and its local checksum helper is read-only.

Source checkouts and artifact output roots must resolve outside the application tree and must not overlap each other. The engine checks the exact upstream origin, full commit SHA, tree SHA, clean Git status including untracked files, and pinned source-file hashes. It rejects stale build paths, unknown recipes, configuration changes, unresolved/mismatched Kconfig, missing/extra/colliding X200 ROM outputs, symlinks, incorrect image sizes, altered copied artifact hashes, and incomplete or changed X220 IFD region maps. Every selected X200/X220 image must also pass strict parsing of the pinned Coreboot `cbfstool print -k` tab-separated inventory. X200 requires exactly one `fallback/payload` entry of type `simple elf`; X220 requires that entry to have type `payload`. The manifest records the executable digest, parser-source digests, repository, commit/tree, region and full inventory. X220 additionally validates the original backup's descriptor map and requires its exact descriptor/ME/GbE slices, then compares every generated non-BIOS region byte-for-byte against that full-chip original. Build logs and artifact/manifest checksums are recorded. Build subprocesses receive a reduced environment; no dependency installer is invoked. Build attempts may leave ignored/generated files in the supplied upstream checkout; a failed or completed checkout is not reusable until restored to a fresh clean state.

## Build and safety boundaries

- Only the exact three profiles above are accepted. T430 has no compiled or downloadable ROM recipe.
- Build source and output directories cannot be inside the AutoLoader application tree and must be disjoint.
- X200 requires the chosen recipe's exact observed chip capacity and parsed CBFS payload inventory. X220 additionally requires the 8 MiB device capacity, complete matching original full-chip backup, exact descriptor/ME/GbE slices from that backup, and the complete observed IFD/GBE/ME/BIOS region map; original and generated maps must match it exactly, and non-BIOS regions must be byte-preserved.
- A complete software build result requires an artifact record and a complete immutable manifest. Failures keep their command logs and failure code/detail. Reproducibility is explicitly `not_attempted`; a single build would not prove reproducibility.
- At Phase 04 acceptance, the artifact engine had no writer boundary. This phase does not authorize `flashrom`, internal flashing, backup restoration, IVprep, or recovery; Phase 10B later adds a separate guarded X200/X220 external writer.
- Phase 08 integrates the engine into explicit CLI/TUI X200/X220 build and artifact-acceptance actions, bound to fresh intent and verified backup evidence. Native Windows build requests return `LINUX_BUILD_ENV_REQUIRED` before spawning a build command or creating output. Ubuntu 26.04 WSL is available.
